# Historical journey evidence: preservation and recovery audit

5 November 2026. Authorised scope: read-only lifecycle/recovery audit, bounded preservation correction, regression validation and unmerged PR. No Stage 3 implementation.

## Outcome and evidence limits

Starting main independently verified through GitHub: **751f83fe3c33160b1ff8cfcf7e3e16349e15773b**, merged #281; its source tree is **6359ecbabe95f70b9599bf7d67ec425a3c685a23**. #280 is incorporated through #281's first parent, 870edf535bceb5399ab694aafd13621c882c0328. Historical Timeline journeys are **not universally unusable and not demonstrated permanently lost**. Original export reprocessing is a viable recovery source for fields actually present. Full native archive records may contain substantially more than achievement projections expose. No private archive, original private export, phone filesystem or production location database was accessed. Recovery categories below are code/fixture conclusions, not measured proportions of the owner's history.

There is currently no production historical Timeline validator. The merged Stage 2 native adapter intentionally rejects Timeline records, even when complete and even if they have timestamps. Preserving timestamps does not implement trustworthy local movement, gap, correction or source validation. A future historical adapter must establish those facts independently. Stage 1 has 889 research candidates and **zero eligible physical targets**; no production journey can currently produce a real discovery.

Neither Timeline path times nor decimal coordinate digits establish sensor accuracy. Per-point precision must distinguish supplied representation, timestamp rounding and actual measurement uncertainty. No constant accuracy may be supplied just to pass CaptureQualityValidator. Source confidence is not a substitute for local section validation. Running's normalized mode remains walking to preserve IDs, matching and visible history.

## 4. Bounded implementation and demonstrated recovery

The only production change adds a separate preservation envelope to **newly constructed accepted Android imports**. It does not edit modeFor, ID, route, source distance, stage status, request, matcher, NCN hash, achievement reader or backend contract. It does not attach the new envelope to completed existing journeys; old reimport guards remain. The new helper copies bounded scalar metadata and a detached aligned time array, preserving equal/reversed/gapped supplied times as unvalidated facts, while rejecting missing/invalid/unaligned arrays. It never stores an inferred accuracy or fills a missing sample time.

This is a **partial preservation correction**, not the proposed complete raw-source layer. Consecutive duplicate observations, original path blocks and literal point times were already removed before this hook. The field name does not change that limitation: `route_point_times_ms` indexes the imported deduplicated route and its potentially inferred endpoint anchors. No source filename, URI, private export or unbounded arbitrary source object is copied.

Demonstration: synthetic semantic walking/running/cycling/bus exports are read by the actual file reader, saved and reopened without the input file; source labels/boundary strings/aligned times survive. Legacy string-array waypoint fixture retains RUNNING/HIGH without inventing local times; object waypoint fixture documents existing unsupported extraction. Reimport of an already completed corrected old record preserves identical stored JSON, ID and archive revision. Metadata-only update leaves NCN evidence revision unchanged; deletion removes the envelope with the journey file. These are local fixture demonstrations, **not private historical recovery**.

## 5. Preservation architecture for subsequent work

Use existing app-private files and atomic store patterns first. No cloud archive, new service, message queue or giant SQL migration is justified by this audit.

| Layer | Smallest useful representation | Identity / reprocessing |
| --- | --- | --- |
| Source | Versioned per-source/per-journey blocks: original coordinate values without new quantization, literal/typed supplied time + representation precision, nullable accuracy/speed, exact activity assertion/confidence, source format/revision, original segment/sample ordinal, gaps/boundaries, parser revision, content digest and observed source identity. Distinguish anchors from observations. | Stable opaque journey ID + independent source-record/content digest and source-to-sample map. URI/path fingerprint is provenance hint only. Hash is integrity/identity, not authenticity. |
| Validated | Validator revision and source token; finite accepted original sample ranges, local mode support, quality status/reasons, excluded ranges/gaps and observation-to-section mapping. Preserve unresolved outcomes. | Recompute when source or rules change. Missing accuracy/timestamps need a historically justified validation policy; never substitute native-quality defaults. |
| Derived | Matcher results, supported road/NCN intervals, settlements and compact milepost proof references. | Key by source token + validator/algorithm/reference/policy revision; rebuild independently, do not rewrite source or duplicate contribution owners. |

Original export reprocessing should first build a bounded local source index, then stage enhancements for existing IDs. Do not persist the entire export plus every redundant JSON copy. Lossless compression of chunked samples is appropriate; fixed-point/delta representation only at exact supplied precision, or with explicit reversible encoding. Millisecond conversion alone is lossy for higher-precision source strings. Preserve duplicate/time-order/boundary distinctions even when render geometry omits them. For native evidence, arrays already duplicate raw geometry and cleaned geometry; remove redundancy only through a separately verified format migration with old readers, never in this patch.

Proposed budgets for a later reader (not measured device acceptance): <=1MiB decoded source chunk, <=10,000 observations per chunk, <=256-character metadata scalars, bounded nesting and one journey/chunk active; larger recordings split with explicit boundary links, never silently discarded or joined. Match Stage 2's current 10,000-point adapter limit unless that adapter is separately extended. Stream byte/vertex limits before JSON allocation; the existing importer is not fully bounded because it holds semantic segments plus globally sorted path points. This patch bounds only its added envelope.

Compression trades CPU for disk; keep chunk metadata/indices small and cache only bounded validated sections. Prefer per-journey sidecar/chunk data with atomic manifest pointer if full source retention grows beyond the current record; schema migration must be restartable and not delete old bytes until verified. Source indices need identity/time retrieval; future marker R-tree indexes public marker candidates, not a permanent second copy of all private coordinates.

App-private storage, no automatic raw upload, explicit export permission, local retention controls and deletion across source/validated/derived caches are required. Deletion/correction tombstones must invalidate staged work and prevent implicit resurrection by source reimport; an explicit user-requested restore is a separate operation. Review diagnostics/internal resort/ferry copies and OS backup rules before claiming comprehensive erasure. Proposed long-term retention: one faithful source representation while the user retains that history, bounded current/previous validated and derived cache generations, no unlimited duplicates. No universal byte/device storage estimate is supported without a representative local count-only sample.

Imported JSON is untrusted: reject excessive bytes/nesting/counts, malformed coordinates and unsupported schemas before allocating; retain unknown precision as unknown; never deserialize `validated=true` into trust. Source identity checks are not proof of genuine travel; keep imported and app-native trust boundaries distinct. Work off UI/capture threads, support cancellation and atomic revision rechecks, and never log precise locations or source names into CI reports.

## 6. Recovery/migration plan without duplicate journeys or credit

1. **Read-only local inventory**: bounded projected reader reports schema, field availability, per-section A–E/reasons and aggregate counts only; no user coordinates exported. Confirm actual retained source formats, diagnostics availability and installed-version provenance. Preserve count-only receipts.
2. **Future source ingress**: lossless original observations/labels/precision/boundary provenance for new imports before normalization; old readers remain supported. Keep this PR's envelope as a legacy partial schema, not a validator.
3. **Dry-run source reconciliation**: generate the existing deterministic ID using unchanged algorithm, require compatible source type/interval/endpoint/mode evidence and exact association. Same-ID conflicts, changed normalized labels/endpoints, overlapping segments and duplicate export variants require held ambiguity; do not fuzzy-join on proximity or URI. Original ordinal/content digest may deduplicate repeated source records but must not replace journey IDs.
4. **Evidence-only staged backfill**: attach source sidecar to existing ID under store lock and expected source/revision token; leave titles/corrections/matches/distance/coverage/entitlements untouched. Save idempotent content hashes, bounded cursor, backup/rollback manifest. Do not call normal import to create unmatched new journeys during recovery. Unknown/deleted IDs are skipped/held, never recreated automatically.
5. **Historical validator**: verify local movement/mode/time precision/gaps with source-specific rules, map user exclusions to original sections, preserve safe subsets and explicit unsupported ranges. Test real redacted format shapes before accepting. New source evidence must not silently rematch an old journey or change road credit.
6. **Versioned derived reassessment**: existing road contributions stay keyed by existing journey ID. If a separately authorised rematch is needed, atomically replace that journey's contribution, never append a duplicate. Milepost proofs reference source/validator versions and retract on correction/deletion with resumable checkpoints and concurrent-change detection.

No wholesale reimport/migration is implemented or authorised by this PR. No recoverability percentage, inventory size or claimed amount of historical recovered distance is supplied.

## 7. Historical milepost scenarios and Stage 3 dependency recommendation

| Scenario | Expected result / validation evidence |
| --- | --- |
| Historical walking/cycling with independently trustworthy geometry | Typed historical Evidence can qualify; existing synthetic Stage 2 independent-section, cycle and 100m boundary fixtures retained. Production historical validator still absent. |
| Running source | Original RUNNING now persists on new import; effective mode remains walking. Source-label preservation does not establish movement by itself. |
| Simplified line or missing local timestamps | No production Timeline qualification; helper refuses missing/invalid timestamp arrays. A line or interval is not original observation proof. |
| Unsupported gap | Preserve gap in source facts; never connect it for proximity. Existing native gap/finite disconnected-section tests hold or reject. |
| Uncertain activity | Original assertion/probability retained if supplied; unknown/vehicle activity does not become eligible merely through a label. Historical uncertainty remains unresolved. |
| Existing-journey reimport | Stable ID and unchanged completed correction/title/match; no duplicate journey. No new historical backfill in this patch. |
| Corrected/deleted | Native Stage 2 holds unsupported edits; archive deletion removes new field with record. No ledger exists here, so durable proof retraction is future work. Existing reimport-after-deletion behavior requires tombstones in a recovery worker. |
| Eligible/datable marker within 100m | Independently validated finite section qualifies, with no seeing/stopping/photo requirement. Stage 1 real candidates stay ineligible; no awards written. |

**Do not block all ledger engineering on recovering every historic journey.** Essential ledger contracts: stable journey/source/validation/catalogue/policy tokens; atomic proof replacement/retraction, duplicate physical-ID prevention, explicit unresolved/deleted outcomes, bounded reader/cursor and correction/deletion invalidation. The ledger can be built/tested against synthetic and qualifying native evidence while a historical adapter is unavailable, provided it records historical assessment as pending/unresolved and supports later backfill. This audit does not begin that work.

Historical source recovery/validator is essential **before claiming historical coverage complete or activating retrospective Timeline discoveries**, not necessarily before writing an isolated inactive ledger. Reviewed eligible physical IDs/aliases and dated marker presence/location are essential before actual discoveries. Spatial index and device budgets are essential before a production archive scan. Update the Stage 3 brief to make these distinctions explicit; do not promote the new unvalidated envelope into the Stage 2 typed validator.

Recommended order: preservation PR review/integration; local inventory + source-ingress/identity design; historical reader/reconciliation/validation and deletion semantics; inactive ledger development with native/synthetic contracts (can proceed independently once contracts settle); reviewed eligible catalogue + index; integrated device/backfill/performance/accessibility validation; separately authorised activation.
