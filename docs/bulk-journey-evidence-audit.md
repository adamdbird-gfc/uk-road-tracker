# Journey evidence audit

Reviewed Android release tag `roadprints-0.25.268-314` (source `8694493d`, tested Android source `759aff60`) and LAB r432 (`eb259882`, PR #432). The release receipt reports version 314 and application ID `com.roadprints.capture`. The r432 main branch has Android version metadata for build 286 and lacks later release work. The Android change is based on the 314 tag to preserve the released Map and Utilities. Pixel installation, live matcher deployment and current reference-data pins were not measured in this audit. Neither feature depends on changing those services.

| Evidence | What the archive retains |
| --- | --- |
| Recorded coordinates | `route_geometry` is the saved input, sometimes cleaned or edited. Modern device captures additionally retain `raw_capture_geometry`, `raw_capture_samples` and cleaned `capture_route_samples`. The samples can include accuracy, epoch milliseconds, speed, provider and elapsed-realtime metadata. Raw here means fixes retained by capture. Rejected or unrecorded fixes are unrecoverable. |
| Timeline coordinates and time | Timeline stores imported coordinates and trip timestamps. Newer imports can retain `timeline_source_evidence` and aligned `timeline_match_evidence.point_times_ms`. Historical imports can have only sparse source coordinates and no point times or accuracy. |
| Movement and provenance | Stable journey ID, journey timestamps, timezone, mode and source. Capture decisions, activity history, quality/validation, stop, station, and ferry evidence vary by vintage and source. Movement diagnostics outside the journey store have separate retention and provenance. |
| Match geometry | The current `processing_result.geojson` has ordered matched LineString or MultiLineString components when the retained match produced them. Corrections can remove numbered matched edges or replace matcher input; preserve them alongside the saved match. The store has no complete version history of superseded matches. |
| Network references | `road_geojson`, motorway/A-road GeoJSON, cycling GeoJSON and versioned `matched_path_evidence` / `cycling_path_evidence` appear when the relevant matcher stored them. Road references may have names and types without stable OSM way/node IDs. A classified reference is not necessarily an ordered route. Railway intelligence can retain itinerary or distance provenance without ordered rail geometry. |
| Matcher outcomes | Store the saved result and its properties, including confidence where present, latest `last_match_attempt`, current processing state, errors, and retry state where retained. A success can clear a previous error. Older journeys do not retain complete request/response histories, candidate rankings or rejected alternatives. |
| Existing exports | Single-journey diagnostics streams one saved JSON record. The backup is a restore-oriented archive. The r432 Lab consumes a derived archive and optionally one private walking diagnostics overlay. Its cumulative interval ledger does not encode a continuous path. |

Two owner diagnostics were checked privately. The priority historical walking journey had five Timeline coordinates and one saved 138-point walking line with classified references. It had no stored point timing, raw capture samples, or modern matched-path envelope. A November 2026 device-captured walk had 138 cleaned samples, raw capture evidence, and a 276-point matched line, with route confidence and a matched-path envelope. These records remain outside source control.

Build the bulk format from the stored journey objects. Report absence explicitly, preserve all retained evidence, and keep the Lab display separate from cumulative attribution. A missing historical field stays missing.
