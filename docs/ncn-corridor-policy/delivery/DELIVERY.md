## Chapel Lane: finite proof and implementation

The previous beyond-edge projection was a real diagnostic limitation. The recovered current rows resolve its ownership without extrapolating travel:

1. Current OSM way **4471919 version 9**, exact nodes/coordinates/hash match the revision-4 source. Relation **75880 version 747** contains both 4471919 and connected **169004647** as NCN1. Observation URLs, tags and relevant membership entries are embedded in [review](chapel-review.json).
2. Source node **27412821** is the final vertex of Chapel Lane and first vertex of admitted 169004647. The publisher target terminates at exactly the first endpoint of the next target; full original graph confirms degree two. This is the same verified road junction represented about 1.94 ground metres apart, not an unrelated nearby road or branch.
3. Pin source stations **[251.09577163400854, 258.7990182846317]**, the final finite edge only. Bind to target `open-edge:96aac48b8463b443ba916d6dbb020a5118f70a5abc29a814e5e1c00a680a9bf1` over the residual above. The earlier 29 bindings are untouched. Source edge length is 7.703247 in operational metric units (7.794464 ground m); the target residual is 8.882678 route-local m. Neither is a changed journey distance.
4. Ordered linear correspondence stays within **1.808 operational metres** throughout: the affine point-difference norm is bounded by its two endpoint norms, 1.182890 and 1.807821 m. Both finite source endpoints and the actual connected junction are used. The ordinary compiler still rejects this pair at its unchanged 15° gate; this is a pinned reviewed exception only.
5. [Compiler](../../../scripts/ncn_chapel_correspondence.py) requires the complete original revision-4 database hash, immutable review hash, unchanged source/adjacent-source rows, modes, target lengths/coordinates and canonical mappings. It refuses existing/same output, and writes a separate candidate. It cannot publish, change source admission elsewhere, recalculate journeys or award achievements.
6. [Independent every-row audit](verify_candidate.py) confirms **one changed paths row and zero changes in routes, nodes, network, meta, targets or overview**. Input artifact stays untouched. [Union impact](chapel-impact.json) scans other sources and route identities sharing the affected canonical geometry; it does not sum route totals.

The candidate uses the existing binding format. Future publication needs the normal package/integrity and owner-authorised publication safeguards; this PR does not alter revision 4 or select the candidate in production.
